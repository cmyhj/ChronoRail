# ChronoRail 优化方案

## 当前问题

### 1. 冗余的手动更新按钮
"一键更新"按钮出现在 3 个地方（Header、Sidebar、MobileDrawer），单游戏刷新按钮也出现在 3 个地方（Sidebar、MobileDrawer、GameCard）。但页面加载时已有自动同步（`App.tsx:194`），这些手动按钮基本冗余。

### 2. 单游戏刷新功能有缺陷
`fetchFromMihoyo` 只能**添加**新版本，**不能更新**已有版本（无 endDate、name 更新）。而全局 `syncFromMihoyo` 两者都能做。用户点单游戏刷新按钮会误以为数据已最新。

### 3. 路由切换清缓存是浪费
`App.tsx:189` 每次路由切换都调用 `mihoyoService.clearCache()`，但数据源是 CI 部署的静态 JSON 文件，缓存永远无法生效，造成多余请求。

### 4. GitHub 同步与版本同步完全割裂
从 GitHub 拉取数据后不会触发 mihoyo 版本同步，反之亦然。两个"更新"概念没有协调。

### 5. 刷新状态逻辑重复 3 次
Sidebar、MobileDrawer、GameCard 各自维护一套 `refreshingId` / `refreshStatus` 状态，代码重复。

---

## 优化方案

### A. 移除手动更新按钮
- 删除 Header 中的"一键更新"按钮
- 删除 Sidebar 底部的"一键更新"按钮
- 删除 MobileDrawer 中的"一键更新"按钮
- 删除 Sidebar、MobileDrawer、GameCard 中的单游戏刷新按钮
- 删除 App.tsx 中 `handleSyncAll` 和 `handleFetchFromMihoyo` 回调
- 保留 `onRefreshGame` / `onSyncAll` props 的移除（清理接口）

### B. 增强自动同步
- 移除 `chronorail_last_sync` 日期检查，每次打开页面都静默同步
- mihoyo.ts 的 5 分钟缓存防重复请求
- 仅在有新增或更新版本时显示 Toast（保留当前逻辑）
- 自动同步使用 `syncFromMihoyo`（完整同步，含 endDate 更新）

### C. 移除路由切换清缓存
- 删除 `RouteWatcher` 组件和 `handleRouteChange`
- mihoyo.ts 的 5 分钟缓存将正常生效，减少冗余请求

### D. 清理 Sidebar/MobileDrawer/GameCard
- 移除所有刷新相关的状态和逻辑
- 简化组件，减少代码量

---
